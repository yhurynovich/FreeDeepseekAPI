# Session Management Guide for FreeDeepseekAPI Callers

This guide explains how to use the `user` field (agent ID) for session isolation, understand session lifecycle, and manage sessions via API endpoints.

---

## Quick Start: Supplying Your Agent ID

### OpenAI Chat Completions (`POST /v1/chat/completions`)

Include the `user` field in your request body:

```json
{
  "model": "deepseek-web-v3",
  "messages": [{"role": "user", "content": "Hello"}],
  "user": "my-agent-name",
  "stream": false
}
```

**curl example:**
```bash
curl -s http://127.0.0.1:9655/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-web-v3",
    "messages": [{"role": "user", "content": "What is my IP?"}],
    "user": "security-guy",
    "stream": false
  }'
```

### Anthropic Messages (`POST /v1/messages`)

Include `user_id` in the `metadata` object:

```json
{
  "model": "deepseek-chat",
  "max_tokens": 1024,
  "messages": [{"role": "user", "content": "Hello"}],
  "metadata": {"user_id": "my-agent-name"}
}
```

**curl example:**
```bash
curl -s http://127.0.0.1:9655/v1/messages \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer dummy-key" \
  -d '{
    "model": "deepseek-chat",
    "max_tokens": 1024,
    "messages": [{"role": "user", "content": "What is my IP?"}],
    "metadata": {"user_id": "security-guy"}
  }'
```

### OpenAI Responses API (`POST /v1/responses`)

Include agent ID in the request (the proxy extracts it for session management):

```json
{
  "model": "deepseek-chat",
  "input": "Hello",
  "user": "my-agent-name"
}
```

### Hermes Agent Configuration

In your Hermes agent config YAML:

```yaml
model:
  default: deepseek-web-v3
  provider: custom
  base_url: http://127.0.0.1:9655/v1
  model: deepseek-web-v3
providers: {}
fallback_providers: []
```

The agent's profile name (e.g., `security-guy`) is automatically sent as the `user` field.

## Session Lifecycle

### Automatic Session Creation

- **First request** with a new `user` value → Creates new DeepSeek web chat session
- Session ID is generated by DeepSeek (UUID), not controllable by caller
- Session persists in proxy memory keyed by agent ID

### Session Reuse & Threading

- Subsequent requests with same `user` → Reuse existing session
- `parent_message_id` tracks conversation threading automatically
- Context preserved across requests automatically

### Auto-Reset Triggers

| Trigger | Threshold | Behavior |
|---------|-----------|----------|
| Message count | ≥ 100 messages | Creates new DeepSeek session, preserves last 15 exchanges locally |
| Session age | > 2 hours | Creates new DeepSeek session, preserves last 15 exchanges locally |
| HTTP 400/404/500 | On error | Resets session, retries once with new session |
| Empty response | Up to 2 retries (configurable) | Compacts context, resets session, retries |

### History Preservation on Reset

When a session resets (auto or manual), the proxy preserves:
- Last 15 user/assistant exchanges
- Up to 10,000 characters total
- Injected as context on next request if client doesn't send multi-turn history

## Session Management Endpoints

### List Active Sessions

```bash
curl -s http://127.0.0.1:9655/v1/sessions
```

**Response:**
```json
{
  "agents": [
    {
      "agent": "security-guy",
      "session_id": "uuid-from-deepseek",
      "message_count": 42,
      "history_size": 5,
      "age_min": 23
    }
  ],
  "total": 1
}
```

**Fields:**
- `agent` — Your agent ID (from `user` field)
- `session_id` — DeepSeek web session UUID
- `message_count` — Messages in current session (0-100)
- `history_size` — Exchanges preserved in local buffer (0-15)
- `age_min` — Session age in minutes

### Reset Specific Agent Session

```bash
curl -s -X POST "http://127.0.0.1:9655/reset-session?agent=security-guy"
```

**Response:**
```json
{
  "status": "session_reset",
  "agent": "security-guy",
  "history_preserved": 5,
  "history": "user msg 1 | user msg 2 | ..."
}
```

### Reset All Sessions

```bash
curl -s -X POST "http://127.0.0.1:9655/reset-session?agent=all"
```

**Response:**
```json
{
  "status": "all_sessions_cleared",
  "count": 3
}
```

## Best Practices

### 1. Use Consistent Agent IDs

- Same `user` value = same session = preserved context
- Different `user` values = isolated sessions = no context leakage
- Recommended: Use stable identifiers like `agent-name`, `user-123`, `session-abc`

### 2. Monitor Session Health

```bash
# Check sessions periodically
curl -s http://127.0.0.1:9655/v1/sessions | jq '.agents[] | {agent, message_count, age_min}'
```

Watch for:
- `message_count` approaching 100 (auto-reset imminent)
- `age_min` approaching 120 (2-hour TTL)
- Missing agents (may indicate idle cleanup)

### 3. Handle Rate Limit / Cooldown Errors

The proxy returns specific error types:

| HTTP | Error Type | Action |
|------|------------|--------|
| 429 | `rate_limit` | Wait `retryAfter` seconds, then retry |
| 503 | `no_auth` | Re-run `npm run auth` or `npm run auth:import` |

```bash
# Check for retry-after header
curl -v http://127.0.0.1:9655/v1/chat/completions ...
# Look for: Retry-After: 60
```

### 4. Force New Session When Needed

If you need a completely fresh context (not just history truncation):

```bash
curl -s -X POST "http://127.0.0.1:9655/reset-session?agent=my-agent"
# Next request with same agent ID will create brand new DeepSeek session
```

## Common Patterns

### Multi-Agent Setup (e.g., Hermes Swarm)

Each agent uses its profile name as `user`:

```yaml
# Agent 1: researcher
model:
  base_url: http://127.0.0.1:9655/v1
  # user: "researcher" (auto from profile)

# Agent 2: coder
model:
  base_url: http://127.0.0.1:9655/v1
  # user: "coder" (auto from profile)

# Agent 3: reviewer
model:
  base_url: http://127.0.0.1:9655/v1
  # user: "reviewer" (auto from profile)
```

All three agents maintain completely independent DeepSeek sessions.

### Long-Running Conversations

For conversations exceeding 100 messages or 2 hours:

1. **Let auto-reset handle it** — Proxy preserves last 15 exchanges
2. **Proactively reset** — Call `/reset-session` before hitting limits
3. **Send full history** — Include all prior messages in `messages` array (bypasses local buffer)

### Debugging Session Issues

```bash
# 1. List all sessions
curl -s http://127.0.0.1:9655/v1/sessions | jq .

# 2. Check server logs for session events
# Look for: "Created new session:", "Reusing session:", "Session ... reset"

# 3. Reset problematic session
curl -s -X POST "http://127.0.0.1:9655/reset-session?agent=problematic-agent"

# 4. Verify fresh session on next request
curl -s http://127.0.0.1:9655/v1/sessions | jq '.agents[] | select(.agent=="problematic-agent")'
```

## Configuration Reference

Environment variables affecting sessions:

| Variable | Default | Description |
|----------|---------|-------------|
| `MAX_MESSAGE_DEPTH` | 100 | Auto-reset after N messages |
| `SESSION_TTL_MS` | 7200000 (2h) | Auto-reset after N milliseconds |
| `MAX_HISTORY_LENGTH` | 15 | Exchanges preserved on reset |
| `MAX_HISTORY_CHARS` | 10000 | Max chars in history buffer |
| `DEEPSEEK_MAX_RETRIES` | 2 | Empty response retries before giving up |
| `DEEPSEEK_MAX_PROMPT_CHARS` | 80000 | Max upstream prompt size |
